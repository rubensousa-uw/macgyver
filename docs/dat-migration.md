# DAT 0.9.0 migration record

This records the Android move from DAT 0.4.0 to the explicitly pinned 0.9.0 release. It is compilation and MockDeviceKit readiness work only; it does not verify Meta Adventurer hardware.

## Official changelog decisions

The selected release is the stable `0.9.0` artifact published on 2026-08-03. The complete interval was reviewed in Meta's [official Android DAT changelog at release commit `81dfb51`](https://github.com/facebook/meta-wearables-dat-android/blob/81dfb51/CHANGELOG.md), from the pinned `0.4.0` baseline through `0.9.0`.

| Version | Relevant change | Code decision |
| --- | --- | --- |
| 0.4 baseline | Registration already takes an `Activity`; `AutoDeviceSelector` has a compatibility filter; `VideoFrame` carries presentation timing. | Keep the existing activity-based registration and selector path. This migration does not change phone-camera, registration, or timing behavior. |
| 0.5 | `Device.linkState` replaces the boolean availability signal; photo capture returns typed `DatResult<PhotoData, CaptureError>`. | Keep flow-based device observation and typed `.onSuccess`/`.onFailure` photo handling. No error descriptions are parsed for control flow. |
| 0.6 | Session-based device management (`Wearables.createSession`, `Session`, and session state); `StreamConfiguration.compressVideo` and `VideoFrame.isCompressed`; typed permission results; `MockDeviceKit.enable/disable` and camera services. | Follow the later 0.7 rename to `DeviceSession`/`DeviceSessionState`, replace the removed factory with an explicit session, and wait for `DeviceSessionState.STARTED` before attaching the camera. Request `compressVideo = false`, reject compressed frames, preserve typed permission handling, and keep the existing MockDeviceKit surface on the pinned version. |
| 0.7 | DAM was introduced; registration errors moved to `Wearables.registrationErrorStream`; device state/thermal state and typed session/stream errors were added; `Stream.start()` became explicit and `VideoFrame.isCodecConfig` identifies codec-only frames. | Camera code uses explicit `Stream.start()` and rejects codec-configuration frames. Registration/error and device-state expansion remains outside this migration story; no display capability or DAM opt-out is added. |
| 0.8 | `DeviceType.META_GLASSES`, `StreamState.PAUSED`, capability `stop()`, and unified `MockDeviceKit.pairGlasses(model)` were added. | Do not hard-code Adventurer selection here; Story 2.2 owns `META_GLASSES` selection. Use `StreamState`, stop capabilities directly, and use the 0.9-compatible MockDeviceKit factory in focused tests. |
| 0.9 | `DeviceSession.addStream/removeStream` were removed for `addCamera/removeCamera`; `Camera.stream` is the child stream; camera stop and crash-reporting opt-out were added; `DatResult` became Java-visible; DAM opt-out support was removed. | Both legacy stream owners create a session, start it, attach a camera, then start `Camera.stream`; teardown first cancels the retired generation's collectors, then stops the camera, removes it, and stops/discards the session. Analytics and crash reporting are opted out in the manifest; no obsolete DAM key is declared. |

`mwdat-mockdevice` remains an `implementation` dependency because the baseline already contains the developer MockDeviceKit ViewModel/screen and `WearablesViewModel` observes its paired-device state. Moving it to a test-only configuration would break those existing app sources; no new production dependency or MockDeviceKit behavior was introduced by this migration.

## Verified API surface

The DAT 0.9.0 SDK source and CameraAccess sample were checked for `Wearables.createSession`, `DeviceSession.start`, `DeviceSession.addCamera`, `Camera.stream.start`, `Camera.stop`, `DeviceSession.removeCamera`, `StreamState`, `VideoFrame.isCompressed`, and `VideoFrame.isCodecConfig`.

All raw-I420 consumers reject compressed or codec-configuration frames and frames whose buffer size is not exactly the contiguous I420 payload size (`width * height * 3 / 2`) for positive, even dimensions. No stream-start state is treated as a usable camera frame. Generation checks discard late callbacks and frames from a retired session, and teardown isolates camera-detach/session-stop failures so later cleanup still runs.
